# Decisions

Rulings made while building admitly, in the format
`Ruling: <what> — <why> — <cost if wrong>`.

- Ruling: Policy documents mirror Kubernetes ValidatingAdmissionPolicy (match, matchConditions, variables, validations with message/messageExpression) under a private `admitly.dev/v1alpha1` group, loaded from files rather than served as real CRDs — anyone who knows VAP can read them, and file loading keeps the webhook free of API-server write access — a cluster-native CRD controller would need RBAC, informers and status reporting that are not built.
- Ruling: Decode policies and admitted objects with `sigs.k8s.io/json` (case-sensitive, strict, ints preserved) instead of `encoding/json` — `encoding/json` matches field names case-insensitively, so a typo like `runAsNonroot` in a mutation default validated cleanly and would have been patched into pods as a field the API server ignores; preserving ints means CEL sees `int` for `params` — none known; it is what the API server itself does.
- Ruling: The CEL environment exposes pre-extracted `podSpec`, `podMeta` and `containers` (init + regular + ephemeral) for Pods and the seven workload kinds — policies stay one-liners that work for Deployments and CronJobs alike without per-kind path logic — a workload kind not in the table (e.g. a custom operator CRD with a pod template) gets `podSpec == null` and must be handled with raw `object` paths.
- Ruling: Sub-resource requests match only rules that list the sub-resource (`subresources: ["", ephemeralcontainers]`) — `kubectl debug` adds containers through `pods/ephemeralcontainers`, a known way around pod admission policies; opting in per rule keeps `pods/status` noise out — a policy author who forgets the opt-in leaves that path open (the built-in privileged/registry/digest policies opt in).
- Ruling: Registry allow-listing matches anchored, component-wise globs on the parsed and normalised repository name (`registry.lab.local/**`), never string prefixes — `startsWith("registry.lab.local")` admits `registry.lab.local.evil.io/x`; a test pins this — none.
- Ruling: The image reference parser rejects anything ambiguous (upper-case host without `.`/`:`, names whose normalised form exceeds 255 chars) instead of guessing — fuzzing found both as canonicalisation round-trip failures; a policy decision on a mis-parsed registry is a bypass — a valid-but-exotic reference used in a real cluster could be denied and need a policy exception.
- Ruling: Per-policy `failurePolicy` (Fail/Ignore) governs evaluation errors; a separate global `failureMode` (Closed/Open) governs requests whose evaluation did not finish before the deadline or that the server could not process — the two failure classes have different owners (policy author vs. platform operator), mirroring the API server's own webhook `failurePolicy` — operators must understand three knobs (policy, admitly, API server) instead of one; docs/THREAT_MODEL.md tabulates them.
- Ruling: A deadline expiring mid-evaluation marks the result Incomplete and never blames the policy that happened to be running — otherwise an overloaded webhook would deny with a misleading per-policy message (or silently skip under Ignore) — none.
- Ruling: Keep the CEL runtime cost limit even though cel-go v0.29.2's cost tracker makes comprehensions O(n²) in time (measured by `go test -run '^$' -bench Comprehension ./internal/celenv/`: 10x elements → ~60-65x time with tracking, ~10x without) — the cost limit is the only machine-independent bound on policy work, and wall time is still capped by the interruptible request deadline and the 3 MiB body cap — large lists in hostile objects can burn CPU up to the deadline on each request; recorded in docs/THREAT_MODEL.md.
- Ruling: Mutation defaults are "set if absent" only and skip `allowPrivilegeEscalation` for privileged/CAP_SYS_ADMIN containers and all Linux fields for Windows pods — the API server rejects `allowPrivilegeEscalation=false` with `privileged=true`, which would turn a clean policy denial into a confusing API validation error — a user expecting the default on such a container will not get it (the privileged policy denies the pod anyway).
- Ruling: The built-in mutation runs on CREATE only — mutating on UPDATE would change pod templates of running Deployments on any unrelated edit and trigger rollouts — workloads created before admitly was installed are not hardened until recreated.
- Ruling: The HTTP handler reads the (size-capped) body and decodes it with a non-streaming Unmarshal, rejecting trailing bytes after the AdmissionReview — the first version used a streaming decoder that silently ignored trailing data, which the handler fuzzer flagged; two parsers disagreeing about where a request ends is how smuggling bugs start — none (the API server never sends trailing data).
- Ruling: `make check` runs the envtest suite only when kube-apiserver/etcd assets are already installed (`setup-envtest use -i`), printing SKIPPED otherwise; `make envtest` downloads them — `make check` must pass offline from a fresh clone, while the envtest binaries are a ~100 MB download — on a machine without assets the API-server integration is not exercised by `make check` (CI runs `make envtest` as its own job).
- Ruling: errcheck ignores `fmt.Fprint*` (CLI/report output) and gosec G304 (file paths come from operator-controlled flags and config); permission findings are fixed (0750/0600) except public keys and signature files, which carry targeted `//nolint:gosec` comments — zero-warning lint without blanket exclusions — none.
- Ruling: Quantity limits are compared with a new `quantityCompare(a, b)` built on `resource.Quantity.Cmp` (exact, arbitrary size), and `quantityMilli` now computes milli-units with `inf.Dec` and returns a CEL error when the result does not fit in int64 (int/double inputs too, plus NaN/Inf) — review fix round 1: `Quantity.MilliValue()` wraps around for quantities above ~8Pi (`10Pi` → -7187745005283311616), so `require-resource-limits` admitted a `10Pi` memory limit while denying `5Gi`; an error lets `failurePolicy` decide, and the built-in policy no longer depends on that path at all — a user policy that keeps using `quantityMilli` with `failurePolicy: Ignore` would skip (not deny) such objects; `quantityMilli` doubles now round away from zero like strings (0.0005 → 1, was 0).
